# M1a — real FULL planner compatibility

The producer remains the unmodified `full_implementation_plan.py` CLI. Tests in
`real_planner_fixture.py` construct **synthetic service specifications and technical
planning inputs**, then invoke that CLI with its consistency guard enabled. They
never materialize the frozen mailing-info fixture. This validates the boundary
starting at the service specification; it does not implement Sparx consolidation
or EA fixtures (M1b–M7).

## Accepted contract

- Plan v3, FULL and functionally ready; parameters v2 with matching service.
- Current workspace spec and archetype fingerprints; mandatory
  `inputs.generationParameters.sha256` and, when declared,
  `inputs.planningInput.sha256`. Parameter provenance must agree with the plan.
- Unique safe paths, known actions, complete dependency inventory and valid
  ordering when supplied. The service model is validated even for retained files.
- Canonical `activityLogging.requestHeaders.roles`. The old `roleMapping` spelling
  is an explicit compatibility alias; conflicting aliases, missing components,
  duplicate role/header assignments or undeclared headers stop generation. The
  report identifies which spelling was used.
- Tests use the semantic component type and its planned production dependencies.
  A controller contract test can therefore keep `<Api>ContractTest`, and a unit
  test may have another valid Java class name. Dependency-free older fixture
  plans retain an explicit name-based fallback. Ambiguity never falls back.

## Baseline ownership

Only the existing Maven assembler renders `build-baseline` (`pom.xml`) and
`logging-baseline` (`src/main/resources/logback.xml`). The materializer delegates
them and checks that every planned write was actually rendered exactly once.

| Action | Behavior |
| --- | --- |
| `create` / `update` | Assemble, check the planner's expected hash when supplied, then use normal file protection and `guard_write`. Manual/untracked conflicting content blocks; it is not silently changed to retain. Identical generated bytes are idempotent. |
| `retain` | Requires an existing file. Preserve it and report it as retained. |
| Unknown action | Reject before writes; never interpret as retain. |

The `--no-assemble` switch cannot omit an explicit baseline write. Maven additions
are rejected as unsupported here rather than silently dropped. `remove`, unknown
components and unsupported functional capabilities still stop FULL generation.
No partial output is presented as FULL.

`application*.properties` exclusion and `guard_write` are unchanged. The real
planner's existing reads/hashes of its technical properties template occur only
on temporary archetype copies in these contract tests, as explicitly authorized.
No configuration values are printed in the test report.

## Verification

`test_m1a_contract.py` tests CLI artifacts, roles and legacy compatibility,
semantic test dispatch, baseline actions, stale inputs, schema failures,
unsupported features, the real consistency gate, manual files, determinism,
idempotency and independent services. It also runs offline Maven on both
synthetic projects and records separate compilation/JUnit/Checkstyle/JaCoCo
evidence through the existing recorder. No planner code or archetype rule is
changed, and Maven never runs on a real service.
